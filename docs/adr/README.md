# ADR (Architecture Decision Records)

하루거래소의 설계 결정과 **포기한 대안**을 남기는 곳이다. 코드는 무엇을 했는지 보여 주지만, 왜 그렇게 했고 무엇을 버렸는지는 보여 주지 않는다. 그 부분을 여기에 적는다.

## 언제 쓰나

다음 중 하나라도 해당하면 ADR을 쓴다.

- 되돌리려면 여러 모듈이나 스키마를 고쳐야 하는 결정 (예: 종목별 단일 스레드 엔진, 명령 로그와 Outbox)
- 대안을 두 개 이상 비교했거나 측정해서 고른 결정 (예: 잔고 잠금 방식 비교)
- 불변식이나 장애 복구 방식에 영향을 주는 결정
- 라이브러리나 프레임워크의 사용 범위를 정한 결정

설정값 하나, 이름 하나처럼 쉽게 되돌릴 수 있는 결정은 PR 본문으로 충분하다.

## 작성 방법

1. [`0000-template.md`](0000-template.md)를 복사해 `NNNN-영문-요약.md`로 저장한다. 번호는 아래 목록의 마지막 번호 다음이다.
2. 상태는 `제안`으로 시작한다. 결정과 함께 PR을 머지할 때 `채택`으로 바꾼다.
3. 아래 목록에 한 줄 추가한다.
4. 결정을 구현하는 PR이 따로 있으면 ADR의 "관련"에 링크한다.

**채택된 ADR의 본문은 고치지 않는다.** 결정이 바뀌면 새 ADR을 쓰고, 이전 ADR의 상태를 `대체됨 (ADR-NNNN)`으로 바꾼다. 오타와 링크 수정은 예외다.

상태: `제안` → `채택` → (`폐기` | `대체됨 (ADR-NNNN)`)
